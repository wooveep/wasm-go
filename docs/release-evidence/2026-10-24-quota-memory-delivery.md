# quota 与账单、记忆事件生命周期修复

状态：Go/Wasm 回归、默认 K3S 全插件 200 并发 / 5 分钟复验通过。日期：2026-10-24（Asia/Shanghai）。全量部署与失败轮证据见 [验收记录](https://github.com/wooveep/modelfusion-deploy/blob/main/docs/checks/2026-10-24-quota-memory-200x5.md)。

## 修改

- **ai-quota 1.0.4**：仅对宿主 Redis 传输失败重试同一只读 GET 一次，不重新初始化共享连接、不重试资金变更；缺少或非正余额、服务端错误、持续失败仍拒绝。正余额恢复、零余额拒绝、持续故障等 Go/Wasm 回归通过。
- **ai-billing 0.1.9 / ai-memory 0.1.3**：响应结束时冻结事件，在插件根 tick 上下文投递 Redis Stream，回调不访问已结束 HTTP 上下文；传输失败只重试一次、保留同一事件身份，结算和采集端继续按幂等键去重。回归主动删除 HTTP 上下文并模拟响应/连接错误，原行为失败、修复后通过。
- 共享队列上限每个配置 1,024 条、256 MiB，包含在途数据，完成后仅释放一次预算。它是内存队列，插件退出、持续 Redis 故障或预算不足仍可能丢事件，不具备持久 outbox 的保证。
- memory 响应头阶段释放组装正文和历史数组，仅保留克隆的小字段；包括随本次合入的 0.1.2 大请求内存修复。资源 schema、README、平台目录与发布版本保持一致，最低协议兼容要求未提高。
