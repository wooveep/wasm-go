# 全插件集成预检修复

状态：代码回归与本轮压测评估完成；财务对账通过，组合稳定性仍有 Redis 503，不能判定全部通过。环境与证据由 `modelfusion-deploy` 维护。

## 已复现与修复

- `ai-billing` 的供应商名称解析只支持 `.dns`。原生 IP 供应商产生 `.internal.static`，内部成本事件缺少供应商事实而进入 DLQ。补齐 `.internal.static` 和 `.static`，保留端口及 slug 校验；不改变定价、账户或幂等处理。
- `ai-history` 无身份时仍读取正文并访问空身份缓存 key。现在在请求头阶段跳过请求及响应正文，避免全局无匹配身份的配置读写共享历史。
- `ai-memory` 在请求组装后仍为整个慢 SSE 生命周期保存完整原始正文与解码消息。近 256K 正文会随在途请求叠加占用线性内存；现在在上游响应头到达时释放组装副本，并复制需要保留的小字符串，避免子串引用持有大缓冲区。提交 `69e9b4e`。

红测覆盖真实静态集群名称解析和无身份请求触发的 Redis 调用；历史插件同一测试同时执行 Go 与 Wasm 模式。两个插件完整测试分别通过，日志保存在部署项目私有压测证据中。

Memory 的生命周期回归先在原实现上失败，再验证响应头阶段已释放副本，同时原始 Envoy 请求正文、图片、记忆注入、SSE 内容/结束标记/usage 和 MemoryEvent 均保持正确；插件完整 Go/Wasm 测试通过。不能仅根据 RSS 高水位判断仍有存活对象泄漏，需结合 Wasm 内存与多轮稳定负载观察。
